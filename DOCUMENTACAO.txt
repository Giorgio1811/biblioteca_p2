1. OBJETIVO E RESULTADO
-----------------------
O sistema administra autores, livros, membros, empréstimos e reservas. A
interface oferece acervo, fluxo de empréstimo e devolução, histórico por
membro, relatório dos livros mais emprestados e dashboard mensal. As regras
de negócio estão implementadas em Python e protegidas por testes.

Os requisitos obrigatórios do guia foram implementados:
  - quatro entidades principais: Autor, Livro, Membro e Emprestimo;
  - ForeignKey e relação reversa autor.livros e membro.emprestimo_set;
  - Admin com list_display, filtros, pesquisa e TabularInline;
  - bloqueio do empréstimo sem cópias;
  - prazo de 14 dias e baixa de uma cópia no empréstimo;
  - devolução com data e reposição de estoque sem duplicação;
  - property esta_atrasado;
  - relatório com annotate() e Count();
  - templates base, acervo, empréstimos e relatório;
  - proteção POST e CSRF nos comandos que alteram dados;
  - testes para regras, telas, admin e ORM;
  - .gitignore, requirements.txt e README.md.

Também foram implementados todos os desafios opcionais:
  1. multa diária calculada com Decimal;
  2. reserva FIFO e prioridade para quem está no início da fila;
  3. e-mail de lembrete dois dias antes do vencimento;
  4. limite de três empréstimos ativos por membro;
  5. dashboard mensal com consulta ORM e Chart.js.

3. PREPARAÇÃO DO AMBIENTE NO WINDOWS
------------------------------------
Abra PowerShell na pasta do projeto:

  cd C:\biblioteca_projeto
  python -m venv venv
  .\venv\Scripts\Activate.ps1
  python -m pip install -r requirements.txt

Se a política do PowerShell impedir a ativação, não é obrigatório ativar o
ambiente; chame o executável explicitamente:

  .\venv\Scripts\python.exe -m pip install -r requirements.txt
  .\venv\Scripts\python.exe manage.py check

O requirements.txt declara Django 5.2.8 ou superior dentro da série 5.2.
O banco local padrão é SQLite (db.sqlite3), criado na primeira migration.
Esse arquivo é ignorado pelo Git. Para banco de produção, configure o projeto
com as variáveis adequadas e nunca grave credenciais em código ou no Git.


4. BANCO DE DADOS E DADOS DE DEMONSTRAÇÃO
-----------------------------------------
Crie e aplique a migration:

  python manage.py makemigrations biblioteca
  python manage.py migrate

O comando de demonstração:

  python manage.py carregar_dados_demo

cria, caso ainda não existam, três autores, cinco livros e três membros. Os
livros fictícios começam com duas cópias totais e disponíveis. O comando é
idempotente: pode ser executado novamente sem criar cópias duplicadas e sem
repor o estoque de livros já existentes. Os endereços example.com são dados
fictícios, apropriados para desenvolvimento e não destinados a envio real.

Crie o administrador:

  python manage.py createsuperuser

Não há uma senha pré-configurada. O Django solicitará nome de usuário, e-mail
e senha no terminal.


5. MODELOS E INTEGRIDADE
------------------------
Autor armazena nome, nacionalidade e data de nascimento opcional.
Livro pertence a um Autor, tem ISBN único, cópias totais e disponíveis. A
restrição de banco impede que as cópias disponíveis ultrapassem o total.
Membro tem e-mail único e data de cadastro automática.
Emprestimo liga um Livro e um Membro, guarda data de retirada, vencimento,
devolução, status e data/hora do lembrete enviado.
Reserva liga Livro e Membro e mantém status e data/hora, permitindo ordenar a
fila pelo instante de criação e pela chave primária em caso de empate.

O related_name "livros" permite autor.livros.all(). Para empréstimos, o nome
reverso padrão é membro.emprestimo_set. A propriedade esta_atrasado não é
coluna: é calculada a cada leitura usando a data local configurada.
Empréstimos devolvidos não aparecem como atrasados.

As mudanças de estoque ocorrem dentro de transações. A baixa usa atualização
condicional no banco, e a devolução muda o empréstimo apenas uma vez. Assim,
cliques repetidos não duplicam cópias nem decrementam abaixo de zero. O banco
também valida que o número disponível não supera o total.


6. ADMINISTRAÇÃO
----------------
Execute:

  python manage.py runserver

Abra:

  http://127.0.0.1:8000/admin/

O Admin apresenta Autor, Livro, Membro, Emprestimo e Reserva. A lista de livros
mostra autor e cópias; filtros e pesquisa facilitam a consulta. Na edição de
um membro, inlines exibem seus empréstimos e reservas. A criação manual de
empréstimos pelo Admin não atualiza o estoque; para empréstimos de operação,
use sempre a tela pública do acervo. O Admin serve para cadastro e inspeção.

Cadastre dados pelo Admin se não usar o comando de demonstração. Mantenha
copias_disponiveis entre zero e copias_totais.


7. FLUXOS DA APLICAÇÃO
----------------------
7.1 Acervo
  A página / lista livros em ordem alfabética e permite escolher o membro.
  Com cópias disponíveis, apresenta a ação Emprestar. Sem cópias, apresenta
  Entrar na fila. A lista também mostra as reservas pendentes em ordem FIFO.

7.2 Empréstimo
  A rota POST /emprestar/<id>/ valida o membro, verifica se o membro tem menos
  de três empréstimos ativos, respeita a primeira reserva pendente e verifica
  o estoque. Se aprovado, registra o prazo de hoje mais 14 dias e diminui o
  estoque atomicamente. Requisições GET recebem HTTP 405, e o formulário usa
  token CSRF.

7.3 Devolução
  A rota POST /devolver/<id>/ grava a data local, muda o status para
  DEVOLVIDO e adiciona uma cópia ao estoque. Uma segunda requisição não muda
  estoque. Após a devolução, a próxima pessoa da fila passa a ter prioridade
  quando a cópia estiver disponível.

7.4 Reservas
  A reserva só é criada se o estoque estiver zerado. O mesmo membro não pode
  entrar duas vezes na fila pendente do mesmo livro. Ao surgir estoque, o
  primeiro membro da fila é o único autorizado a pegar a cópia; o empréstimo
  marca a respectiva reserva como ATENDIDA. A fila não envia notificações
  automáticas quando surge uma cópia; o membro acompanha a tela do acervo.

7.5 Atraso e multa
  O atraso começa no dia seguinte à data prevista. A multa é calculada pela
  property multa, com Decimal e taxa configurada MULTA_DIARIA = "2.00".
  Enquanto não devolvido, contam-se os dias até hoje. Depois da devolução,
  contam-se os dias até data_devolucao. Uma devolução antes ou no vencimento
  resulta em zero dias e R$ 0,00.

7.6 Relatório
  A rota /relatorio/ usa annotate(total_emprestimos=Count("emprestimo")) e
  ordena de forma decrescente pelo total, desempatando por título.

7.7 Dashboard
  A rota /dashboard/ apresenta contadores gerais e agrupa empréstimos por mês
  com TruncMonth e Count no ORM. O gráfico é renderizado com Chart.js carregado
  do CDN jsdelivr; é necessária conexão com a internet para desenhar o gráfico.
  Sem registros, a tela mostra a mensagem de ausência de dados.


8. LEMBRETES POR E-MAIL
-----------------------
O envio é feito por comando de gestão, adequado para ser executado uma vez por
dia por Agendador de Tarefas do Windows, cron ou outro scheduler:

  python manage.py enviar_lembretes

O comando seleciona apenas empréstimos ATIVOS, ainda não devolvidos, com prazo
exatamente daqui a dois dias e sem lembrete registrado. O e-mail só é marcado
como enviado quando o backend confirma o envio. Uma nova execução não duplica
o aviso já confirmado.

Por padrão, o backend é o console do Django: o conteúdo aparece no terminal e
nada é enviado pela internet. Para SMTP, configure as variáveis de ambiente
antes de iniciar o comando:

  DJANGO_EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
  DJANGO_EMAIL_HOST=<servidor SMTP>
  DJANGO_EMAIL_PORT=587
  DJANGO_EMAIL_HOST_USER=<usuário SMTP>
  DJANGO_EMAIL_HOST_PASSWORD=<senha SMTP>
  DJANGO_EMAIL_USE_TLS=true
  DJANGO_DEFAULT_FROM_EMAIL=<endereço remetente>

No PowerShell, defina variáveis na sessão com $env:NOME="valor". Não inclua
senhas no README, no código, neste documento ou no repositório. Em ambiente
real, use o gerenciador seguro de segredos do serviço de hospedagem.


9. TESTES E CHECKPOINTS
-----------------------
Verifique configuração, migrations e testes:

  python manage.py check
  python manage.py makemigrations --check --dry-run
  python manage.py test

O conjunto automatizado contém 14 testes e cobre:
  - prazo de 14 dias, decremento e bloqueio sem estoque;
  - rejeição de GET no endpoint de empréstimo;
  - devolução única e reposição de cópia;
  - cálculo de atraso e exibição do badge;
  - relação reversa, ranking, listagem e registros do Admin;
  - cálculo da multa para empréstimo aberto e já devolvido;
  - limite de três empréstimos ativos;
  - ordem FIFO e prioridade de reserva;
  - envio único dos e-mails de lembrete;
  - dashboard e dados JSON para o gráfico;
  - carga de demonstração repetível.

Fluxo manual de conferência:
  1. Execute carregar_dados_demo e entre no acervo.
  2. Empreste um livro com cópias e confirme redução do estoque.
  3. Empreste até zerar cópias; faça uma reserva e veja a fila.
  4. Tente ignorar o primeiro membro da fila e confirme o bloqueio.
  5. Devolva um empréstimo e confirme que o estoque retorna uma vez.
  6. Acesse os empréstimos do membro e o relatório.
  7. No Admin, ajuste a data prevista para o passado e observe atraso/multa.
  8. Crie um empréstimo com vencimento daqui a dois dias e execute o comando
     de lembretes; com backend padrão, verifique a mensagem no terminal.
  9. Acesse /dashboard/ com algum empréstimo registrado.
 10. Execute novamente python manage.py test.

Para teste local de lembretes, use os endereços fictícios do dataset: o
backend padrão imprime e-mail no console, não os envia externamente.

11. SOLUÇÃO DE PROBLEMAS
------------------------
TemplateDoesNotExist:
  confira biblioteca/templates/biblioteca/ e INSTALLED_APPS.

NoReverseMatch:
  compare o nome do path em biblioteca/urls.py com o nome usado no template.

HTTP 405 ao emprestar/devolver:
  use o formulário POST da tela; não tente abrir a rota no navegador por GET.

Falha CSRF:
  mantenha {% csrf_token %} dentro de cada formulário POST e não desative o
  middleware de proteção.

IntegrityError de ISBN ou e-mail:
  cadastre um valor único. Cada ISBN e e-mail só pode aparecer uma vez.

no such table:
  execute python manage.py migrate.

Sem badge de atraso:
  confirme que o empréstimo não foi devolvido e que a data prevista é anterior
  à data local de hoje.

Gráfico sem renderização:
  confira a conexão com a internet e o carregamento de Chart.js pelo CDN.

Lembrete não enviado:
  o comando só seleciona prazo exatamente dois dias à frente, status ATIVO,
  sem data de devolução e sem lembrete anterior. O backend padrão escreve o
  e-mail no terminal.

Estoque inconsistente:
  revise os dados editados manualmente no Admin. O estoque disponível não pode
  superar o total. Erros ao devolver inconsistências são interrompidos para
  não exibir uma falsa confirmação de sucesso.
